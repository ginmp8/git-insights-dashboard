# Git Insights Dashboard 0.3.0 — candidata na branch de desenvolvimento

**Status:** implementação candidata na branch `feature/0.3.0-incremental-metrics`; **não é uma tag nem um GitHub Release publicado**. Histórico baseado na main após 0.2.0 e nos commits desta branch.

## Novidades

- Primeira aba **Contribuição anual**, com cobertura completa de commits alcançáveis nas referências de integração selecionadas e indicadores por desenvolvedor, sem limite artificial de 500 commits.
- Processamento de diferenças Git em lotes (bruto, `-M`, `-M -w`, status) e armazenamento local em SQLite de commits, arquivos e métricas por SHA e versão do algoritmo.
- Atualização incremental: commits anteriores são reutilizados em consultas posteriores, inclusive após reiniciar o Streamlit; ref é reconciliada em rebases e falhas não promovem resultados incompletos.
- Metadados de autores atualizados conforme `.mailmap` sem reprocessar os diffs já salvos.
- Métricas de mudanças substantivas, mudanças somente cosméticas, churn com movimentações, fonte/testes/docs/gerados, arquivos renomeados, participação em testes e dias ativos.
- Atribuição opcional e explícita de contas GitHub a e-mails Git para PRs mesclados e revisões realizadas/aprovadas, com snapshot persistido após consulta voluntária pela rede.
- Exportação CSV/JSON de indicadores anuais; associação de identidades também persistida.

## Compatibilidade

Os relatórios e filtros legados da 0.2.0 foram preservados, incluindo **Mudanças ajustadas** como diagnóstico rápido. O novo índice SQLite é separado do catálogo JSON, que permanece compatível. Não há alteração nem exclusão de arquivos dos repositórios Git analisados. O mecanismo não executa fetch sem clique explícito.

A variável de versão do pacote foi alinhada a `0.3.0` nesta branch. **Não criar a tag 0.3.0 antes da validação externa**, publicação e decisão de release.

## Pré-requisitos e armazenamento

Python 3.11+, Git e dependências preexistentes da aplicação. SQLite está incluído na biblioteca padrão Python. Para PRs/revisões, GitHub CLI instalado e autenticado. O SQLite fica em `.git-insights-data/annual-metrics.sqlite3`, salvo quando `GIT_INSIGHTS_HOME` for alterado. Preserve o arquivo durante atualizações.

## Ressalvas

- Churn e quantidade de commits/PRs são sinais de atividade, não medidas objetivas de valor individual.
- A análise anual considera cada ref selecionada e usa o **ano da data do autor**; branches descartadas e squash merges podem alterar a atribuição.
- A classificação de arquivos gerados e testes é heurística. O ajuste `-w` pode esconder mudança funcional em linguagens sensíveis a espaços.
- PRs/revisões exigem consulta externa opcional, associação manual de identidades e podem ter cobertura incompleta.
- Renomeações de identificadores da aba detalhada ainda dependem de inspeção específica (não comprovamos equivalência semântica nem cobertura anual desse indicador).
