O [CHANGELOG.md](../CHANGELOG.md) mantém o resumo. Estas páginas documentam versões do projeto; **não são prova de que exista uma tag Git ou um GitHub Release publicado**. Na verificação do repositório em 2026-11-05, a tag v0.2.0 não foi encontrada.

## Convenção para versões futuras

1. Registrar as diferenças e limitações em CHANGELOG.md.
2. Criar releases/X.Y.Z.md com data, principais mudanças, migração, riscos e validação real.
3. Alinhar a versão declarada no pacote e em outras referências do projeto.
4. Executar os testes e registrar as evidências.
5. Criar a tag imutável vX.Y.Z no commit correto e verificar a publicação.
6. Atualizar este índice. O badge dinâmico do README consulta as tags SemVer do GitHub.

Não mover tags publicadas nem substituir arquivos de uma versão já distribuída: publique uma versão corretiva quando necessário.
